# superdeduper (repo root) — AGENTS guide

## Purpose

This is the workspace + binary root for `superdeduper`, a fast cross-platform
duplicate file finder. The root crate publishes the engine library
(`src/lib.rs`) and four binaries (`superdeduper`, `superdeduper-gui`,
`superdeduper-hash-repro`, `superdeduper-dir-probe`); leaf crates that the
optional `telemetry` / bench-real stack depend on without back-importing the
engine live under `crates/`.

Files in scope of THIS audit (root only — not recursing into `src/`, `crates/`,
`tests/`, `scripts/`, `docs/`, `specs/`):

- Top-level governance / orientation markdown (README, CLAUDE, DIRECTIVES,
  HANDOVER, RELEASE, SECURITY, TESTING, CONTRIBUTING, LICENSE)
- Manifest / build glue (`Cargo.toml`, `build.rs`, `rust-toolchain.toml`)
- `schema/submit.schema.json` — generated wire contract derived from
  `leaderboard::submission` structs
- `data/cpu-brackets-catalog.json` — vendored classifier catalog (the
  authoring copy lives in the web repo)

## Files

### `Cargo.toml`

Workspace + package root. Declares the engine package (`superdeduper`
v0.3.42, Rust 1.87, MIT, edition 2021, `publish = false`), four `[[bin]]`
entries, the always-on + optional dep set, six cargo features (`gui`,
`audio`, `telemetry`, `similar-images`, `similar-audio`,
`experimental-similarity-in-gui`), platform-gated deps (`libc` on
`cfg(unix)`, `windows` crate on `cfg(windows)` with a deliberately curated
feature set), build-deps (`image`, `winresource`), dev-deps
(`egui_kittest`, `accesskit`, `proptest`, `tempfile`), four release profiles
(`release`, `bench`, `test inherits=release`, `release-debug`), and the
`[workspace]` block listing the four leaf crates.

- Public API: n/a (manifest)
- Who reads this: `cargo`, `build.rs`, CI workflows, `release.yml`,
  `cross-build-drop.sh`, `check-feature-flag-consistency.sh`.
- Key invariants:
  - `panic = "unwind"` in `[profile.release]` is load-bearing for the
    `audio_hash::tier4` `catch_unwind` shield (commented inline).
  - `[profile.test] inherits = "release"` is required by the 2026-06-05
    Q2 methodology lock (comment cites design 08:50 PDT).
  - `image_hasher = "=3.1.1"` is pinned exact because the
    `fast_resize_unstable` feature is, per upstream, unstable across
    minor versions.
  - `symphonia` features list must include `pcm` separately from `wav`
    (issue #97 v2 — without the `pcm` codec, .wav files probe but
    `decoder.make()` returns Unsupported).
  - `river5` is git-rev-pinned; bump SHA deliberately for any ABI
    change. Local-path override goes in a `.gitignored`
    `.cargo/config.toml` (pattern documented inline).
- Feature gates declared here (consumed throughout `src/`): `gui`,
  `audio`, `telemetry`, `similar-images`, `similar-audio`,
  `experimental-similarity-in-gui`.

### `build.rs`

Compile-time build metadata + app-icon embed. Exposes the current git
short SHA as `SD_BUILD_SHA` (defaults to "dev" outside a git tree),
pre-decodes `assets/sdd.png` to RGBA bytes in `OUT_DIR/app_icon.bin`,
and on Windows targets either invokes `winresource` (native host) or
`x86_64-w64-mingw32-windres` (Linux-host cross-compile path) to embed
`assets/sdd.ico` into the .exe. Skips the icon embed on
`aarch64-pc-windows-*` (no arm64 mingw windres available on the
WSL toolchain).

- Public API: `main`, plus helpers `git_short_sha`,
  `write_app_icon_rgba`, `embed_windows_icon_via_winresource`,
  `embed_windows_icon_via_windres_o`.
- Who calls this: `cargo` at build time.
- Key invariants:
  - The `app_icon.bin` header layout the GUI runtime parses is
    `u32le width || u32le height || w*h*4 RGBA bytes`. See drift note
    below — the module docstring claims a 16-byte header; code writes
    8 bytes.
  - Rerun triggers wired: `.git/HEAD`, `.git/refs`, `assets/sdd.png`,
    `assets/sdd.ico`.
  - Cross-compile path uses `cargo:rustc-link-arg-bins` (an `.o` file
    cargo-zigbuild forwards), NOT a `libresource.a` static archive
    (which zigbuild's linker wrapper rejects).

### `schema/submit.schema.json`

Engine-owned canonical wire contract for `POST /api/v1/submit`.
Generated from `leaderboard::submission` Rust structs
(`RunShape`, `ResultSummary`, `HardwareFingerprint`) via the
`schemars` crate; **never hand-edit**. The
`submission_schema_matches_committed` test in
`src/leaderboard/submission.rs` re-derives the schema and
string-compares against this file — drift fails CI.

- Schema dialect: `https://json-schema.org/draft/2019-09/schema`
- Top-level keys: `hardware`, `run_shape`, `result_summary`
- Locked enum values (consumers depend on these strings):
  - `hardware.disk_class`: NVMe-Gen5 / NVMe-Gen4 / NVMe-Gen3 /
    SATA-SSD / HDD / USB-SSD / USB-HDD / network / mixed
  - `hardware.filesystem`: NTFS / ReFS / exFAT / FAT32 /
    network-SMB / APFS / HFS+ / ext4 / btrfs / xfs / zfs / other
  - `hardware.ram_total_gb_bucket`: power-of-two 4..1024
  - `run_shape.corpus_kind`: user-data / system / canonical-bench
  - `run_shape.scope`: whole-volume / subdirectory / selection /
    canonical-bench
  - `run_shape.walker_variant`: mft / walker / hybrid
  - `run_shape.hash_algorithm`: river5-aes-ni / river5-96 /
    blake3 / sha256 / other
- `result_summary.actions_taken_summary` keys are LOCKED:
  `deleted_to_recycle_bytes`, `deleted_permanently_bytes`,
  `hardlink_replaced_bytes` — web's `lifetime-audit.ts` rejects
  other keys. Use the `ACTION_BYTES_KEY_*` constants instead of
  string literals.

## Invariants / Gotchas

Cross-cutting rules a refactorer at the root must preserve:

1. **Wire schema is engine-canonical.** `schema/submit.schema.json`
   is GENERATED from `RunShape` / `ResultSummary` /
   `HardwareFingerprint` in `src/leaderboard/submission.rs`. A
   struct field change without regenerating the committed schema is
   a CI failure (`submission_schema_matches_committed`). Regen path:
   `SD_UPDATE_SCHEMA=1 cargo test --features telemetry
   submission_schema_matches_committed`.

2. **`actions_taken_summary` key names are wire-locked.** Use the
   `ACTION_BYTES_KEY_*` constants in `leaderboard::submission` —
   web's auditor rejects anything else.

3. **`panic = "unwind"` in `[profile.release]` is required.**
   `audio_hash::tier4` relies on `std::panic::catch_unwind` to shield
   the scan from symphonia decoder panics. Switching to `panic =
   "abort"` silently disables the shield (catch_unwind becomes a
   no-op under abort).

4. **`river5` is git-pinned by rev.** Don't switch to path = `../`
   in the committed manifest; the documented pattern is a
   gitignored `.cargo/config.toml` `[patch."https://..."]` entry.
   The pre-push hook reportedly catches Cargo.lock regressions from
   accidental local-path commits (HANDOVER.md line 78).

5. **`image_hasher` is exact-pinned at `=3.1.1`.** The
   `fast_resize_unstable` feature changes fingerprint values
   between minor versions; bumping requires testdesign to re-run
   the AT-image consistency spec.

6. **Windows verbatim path discipline (S15).** Any ANCHORED path
   match (`starts_with`, drive-anchored glob, depth-by-slash-count)
   MUST route the path through `path_display::for_user_display`
   first or it silently fails on `\\?\C:\...` inputs. Substring
   `.contains()` is leading-prefix-immune.

7. **TODO discipline (S11 + S14).** No comment may make a factual
   claim about other code, other modules, defaults, or invariants.
   Pre-push self-scan is the discipline; review is the safety net.

8. **`build.rs` runs `git rev-parse --short HEAD`.** This requires
   the build tree to be a git checkout OR the build is acceptable
   with `SD_BUILD_SHA="dev"`. Tarball releases get "dev".

## Dependencies

- **INCOMING:** none — this is the workspace root. CI workflows
  (`ci.yml`, `release.yml`), drop scripts (`scripts/cross-build-drop.sh`,
  `scripts/install.sh`), and developer iteration loops consume the
  files here. `src/lib.rs` and `src/main.rs` are the entry points the
  manifest's `[lib]` / `[[bin]]` blocks point at.

- **OUTGOING (workspace internal):**
  - `crates/superdeduper-hmac-signer` (telemetry-gated, leaf crate
    for bench-real submission signing)
  - `crates/superdeduper-log` (NOT optional; always-on log fan-out
    per Mick's 2026-05-29 PERSIST-logs-always directive)
  - `crates/superdeduper-bench-iface` (telemetry-gated trait crate)
  - `crates/superdeduper-bench-real` (telemetry-gated impl crate)

- **OUTGOING (external):** see `Cargo.toml` for the full list; key
  external sources: `river5` (git pin), RustCrypto family
  (`hmac` / `sha2`), egui 0.32 family, symphonia + rusty-chromaprint,
  image + image_hasher.

## Wire Surfaces

- **HTTP — submission endpoint:** `POST /api/v1/submit` on the
  leaderboard backend. Wire contract: `schema/submit.schema.json`.
- **HTTP — classifier catalog:** `GET /api/v1/cpu-brackets/catalog`
  on the web repo (engine vendors the JSON form locally at
  `data/cpu-brackets-catalog.json`).
- **Env vars consumed at the root:**
  - `SD_BUILD_SHA` — emitted by `build.rs` as a `rustc-env` value;
    read at runtime by the GUI header.
  - `SD_UPDATE_SCHEMA=1` — opt-in for the schemars regen test (per
    CONTRIBUTING.md).
  - `CARGO_CFG_TARGET_OS`, `CARGO_CFG_TARGET_ARCH`,
    `CARGO_MANIFEST_DIR`, `OUT_DIR` — read by `build.rs` (standard
    cargo build-script vars).
  - `SUPERDEDUPER_INSTALL_DIR`, `SUPERDEDUPER_VERSION` — read by
    `scripts/install.sh` (out of scope; mentioned in README).
- **Feature flags / cargo features owned here:** `gui`, `audio`,
  `telemetry`, `similar-images`, `similar-audio`,
  `experimental-similarity-in-gui`. The latter defaults OFF per
  Mick's 2026-06-20 directive (Cargo.toml line 214-220).
- **CLI surfaces:** four binaries are declared here (`superdeduper`,
  `superdeduper-gui`, `superdeduper-hash-repro`,
  `superdeduper-dir-probe`); flag-level surfaces are owned in
  `src/cli.rs` and `src/bin/*` — out of root-scope.
